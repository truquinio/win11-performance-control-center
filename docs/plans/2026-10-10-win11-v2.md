# Win11 Performance Control Center v2 Implementation Plan

> **For agentic workers:** Use the host's available task-by-task implementation workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish a safe, observable desktop app using the existing 87-action Windows backend and shared frontend, with meaningful end-to-end evidence rather than cosmetic completion.

**Architecture:** Retain WPF + WebView2 and the .NET ActionCatalog/ActionExecutor security boundary. Refactor the existing TypeScript incrementally after preserving observed behavior in tests. Build the same frontend into local desktop and clearly simulated static DEMO.

**Tech Stack:** Windows 11, .NET 10, WPF, WebView2, TypeScript, Node.js, xUnit, Chromium CDP, PowerShell.

## Global Constraints
- Protect local documents, browser profiles, credentials, running bots and other active emulators. No destructive real-host QA.
- All WRITE actions require explicit confirmation, typed parameters and original interlocks; never expose arbitrary shell IPC.
- Preserve Compact/Developer modes, original assets and working diagnostics.
- Never claim full verification from DEMO alone. UAC, physical DPI and hardware compatibility require separate manual evidence.
- Start QA processes minimized/headless and stop only QA-owned processes. No automatic Windows reboot or unapproved Git push.
- `scripts/verify.ps1` is the integration gate and `scripts/build-local.ps1` creates the installable package.

## Product decisions still requiring explicit approval
- Whether an unattended real Windows WRITE/UAC test is allowed outside a snapshot-capable VM; default is no.
- Whether packaging is only local or should be published as a public GitHub release; default is local.
- Whether action results must survive an app restart; current accepted scope is navigation within one session only.
